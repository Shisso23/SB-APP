# PredictXI admin workspace inventory

Reviewed frontend master at `0f88a48` and backend main at `7f65113`. Both worktrees were clean at kickoff. The live site could not be opened from the browsing environment. Repository routes, server views, tests and the deployment spec drove this inventory.

| Current capability | Purpose and existing API | Supported actions | Usability issue and destination |
| --- | --- | --- | --- |
| Admin entry | `GET /admin/status/` after Firebase restoration. Django enforces staff permissions on workspace APIs. | Retry session check, sign in or out through existing Firebase controls. | Customer navigation duplicated the status check at the admin entrance. A dedicated shell owns admin navigation, account controls and deep links. |
| League scope and coverage | `GET /admin/coverage/?date=` and configured IDs from status. Per-date eligible/predicted counts, job state, published-version notes and separate season freshness. | Pick SAST date, select leagues, select all or eligible, clear, view errors and freshness. | Selection, status and freshness were scattered. Coverage gets a searchable table and shared scope controls for direct actions. |
| Canonical fixtures | Authenticated `GET /fixtures/` with existing filters and pagination. | Read matches, status and scores. Refresh via manual ingestion. | No admin browse view. Fixtures gets a date-scoped browser. |
| Manual execution | `GET/POST /admin/manual/tasks/`. Synchronous per-league requests, SAST daily counts and scoped latest audit. Global catalogue uses league 0. | Catalogue, daily ingestion, odds, predict-and-settle, update final results and progress refresh. API also supports independent settle. | Scope and prerequisites were in one paragraph. Manual Operations presents a run catalogue, scoped actions and progress. |
| Manual forecasts and suggested publication | `POST /admin/manual/predictions/`, `POST/PUT /admin/manual/bet-list/`. Generates one league at a time and previews consolidated successful IDs for the selected batch. | Generate, preview, confirm immutable publication, inspect per-league failures. | Preview was buried. Predictions owns the workflow and links to the official list. |
| Stored forecast inspection | Authenticated `GET /predictions/?history=true`. Canonical versions and saved probabilities. | Read versions by date and league. | Add a bounded, read-only forecast browser with expandable market output. The customer's additive workspace is separate and remains on its existing route. |
| Official picks and performance | `GET /public/official/today/`, `history/`, `summary/` and `preview/`. | Review published list, settled results, and authoritative selection and whole-list statistics. | Official picks were accessible only via the customer site. Add admin read views and retain links to full public history. |
| Historical jobs | `GET /admin/jobs/` and `/admin/jobs/<id>/`. | Read status, source, timings, scope and per-league outcomes. | History was unfiltered and below every other feature. Execution History exposes a clear status filter and expandable details. |
| Schedule scope and ingestion runs | `GET/PUT /admin/ingestion-schedule/`. Latest frontend removed the screen. Repository deployment spec has no scheduled ingestion, dispatcher or admin worker. Legacy `POST /admin/runs/` returns 410. | Store date-specific league scope for daily ingestion and odds or clear to use configured defaults. Scheduled predict-and-settle follows all configured leagues. Read saved slots and ingestion history. | Restore access to existing scope configuration and read records. Times are configured slots, with no implied activation or next-run guarantee. No queue or schedule-time editor. |
| Customers and access grants | `GET /admin/users/`, `POST /admin/users/<id>/grant-access/`. | Search email, UID or ID, paginate, inspect email, unverified phone and account/access, issue audited idempotent grants to eligible users. | Wide directory mixed identities and billing data. Customers separates those details and retains the grant safeguards. |
| Latest purchase attempt | Embedded in `GET /admin/users/` with product, expected amount, provider, attempted/updated dates and lifecycle state. | Inspect latest attempt per account. | Payments makes lifecycle and effective access separate. Admin API provides no settlement ledger, provider reference, confirmed funds total or expired tier history. |
| Access catalogue | `GET/POST /admin/access-products/`, `PATCH /admin/access-products/<code>/`. | View, create active product with confirmation, activate/deactivate. | Dedicated Access Passes retains the server's validation and existing entitlement semantics. |
| Visitor analytics | `GET /admin/visitors/` for paginated visits, recorded-day count and distinct visitor keys. | Read traffic. | Add a paginated Traffic screen with aggregate metrics and recent device/browser entries. Omit network and visitor identifiers from the table. |

Regression priorities include manual request sequencing and server-reported outcomes, immutable publish confirmation, separate public results denominators, recently fixed workspace snapshot restoration, exact grant retry IDs, PayFast, backend email/phone visibility, session switching and admin authorisation. Credentials, payout data and unrestricted operational logs are outside the existing UI contracts.
